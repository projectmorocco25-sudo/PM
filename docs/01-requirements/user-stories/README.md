# User Stories

**Purpose:** This directory contains user stories for all features and modules in the PM platform.

**Last Updated:** 2025-12-31

## Overview

User stories describe features from the perspective of end users. They follow the format: "As a [user type], I want [goal] so that [benefit]." Stories are organized by module and user role to support development prioritization and testing.

## Directory Structure

User stories will be organized by module:
- **RMM (Registry Management Module)** - Stories for registry management workflows
- **VCI (Value Chain Intelligence)** - Stories for submission and monitoring workflows
- **ECS (Export Control System)** - Stories for export authorization workflows
- **CMC (Compliance Monitoring Center)** - Stories for compliance scoring workflows
- **Core Foundation** - Stories for authentication, navigation, and system configuration

## User Roles

User stories are written from the perspective of:
- **Company Admin** - Full company management capabilities
- **Company Manager** - Product/SKU management
- **Company User** - View and limited submission capabilities
- **MOH DMP Tier 1** - Approver/Admin with full administrative capabilities
- **MOH DMP Tier 2 Officer** - Verification, analysis, and escalation
- **MOH DMP Tier 2 Registrar** - Implementation of approved registry changes
- **Auditor** - Read-only access for monitoring and compliance review

## Expected Content

Each user story document should include:
- Story title and ID
- User role
- Story description (As a... I want... So that...)
- Acceptance criteria (or link to acceptance criteria)
- Priority
- Related wireframes and technical specifications
