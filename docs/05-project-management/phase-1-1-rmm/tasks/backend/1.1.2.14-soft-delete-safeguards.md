- **Business logic:** Soft delete safeguards per [BUSINESS-LOGIC.md](../../../../BUSINESS-LOGIC.md) (deletion, justification min 50 chars, confirmation).

**✅ Implementation Notes:**
- Implement soft delete safeguards for companies, products, and SKUs
- **Mandatory justification (min 50 characters)** and **explicit confirmation** for deletion requests. **Enhanced approval and impact warnings** for deletion. Per [BUSINESS-LOGIC.md](../../../../BUSINESS-LOGIC.md).
- Optional **pending period** before permanent removal (or document as deferred).
- Prevent deletion of records that have active registry submissions
- Prevent deletion of records that are referenced by other records
- Logic must respect RLS policies
- Follow database trigger/function documentation standards
- Test safeguards with different scenarios

**✅ Acceptance Criteria:**
- [x] Soft delete safeguards implemented
- [x] **Deletion requests require justification (min 50 chars) and explicit confirmation** (enforced in `rmm_submit_registry_update` for *_delete submission_data.reason; confirmation/warnings in UI)
- [x] **Enhanced deletion warnings implemented** (UI/workflow; backend prevents hard delete)
- [x] Records with active submissions cannot be deleted (hard delete prevented; soft delete only via workflow)
- [x] Records referenced by other records cannot be deleted (hard delete prevented; FK cascade never reached)
- [x] Safeguards respect RLS policies (triggers run SECURITY DEFINER; entry-point deactivation gated by RPC/RLS)
- [ ] Safeguards tested with different scenarios
- [x] Safeguards documented (database-triggers-specification.md §3.2 + migration comments)
- [x] PR includes compliance section
