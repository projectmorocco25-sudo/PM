**2. Component specs (summary)**

- **Header:** Logo, module badge (tooltip full name), search (Ctrl+K), notifications (badge count/dot), user dropdown (Profile, Settings, Logout). All 40×40 min touch targets; focus ring 2px #3b82f6.
- **Sidebar:** Section headers (full name + abbreviation for RMM/VCI/ECS/CMC). Nav items 40px, icon 20×20, label 14px; active #eff6ff + 3px left #3b82f6; hover #f9fafb. Badges (count/dot) supported. Tooltips when collapsed (500ms delay).
- **Notification center:** Unread indicator, title/message/timestamp, type-specific styling. Loading skeleton, error + retry. WCAG 2.1 AA, focus trap, ARIA live regions.

**3. Responsive behavior**

| Breakpoint | Layout | Sidebar | Header |
|------------|--------|---------|--------|
| **Desktop ≥1024px** | Full | Expanded 280px default | Full; module badge visible |
| **Tablet 768–1023px** | Full | Collapsed 64px default | Full; module badge optional |
| **Mobile &lt;768px** | Full width | Hidden; drawer 280px overlay, hamburger | Hamburger left; logo smaller/hidden; search optional or full-screen; notifications full-screen drawer |

**4. Interactions (annotations)**

- Logo → `/dashboard`; module badge → module overview; search → modal (full-screen on mobile); notifications → center popover; user menu → Profile/Settings/Logout.
- Sidebar: nav item → route; collapse toggle → expand/collapse; badge → related page when applicable.
- Notification center: item → related entity + mark read; "Mark all read"; "View All" → `/notifications`; outside/Escape close.

**5. States**

- **Layout:** Sidebar expanded/collapsed; mobile drawer open/closed.
- **Header:** Module badge visible/hidden; notification badge count/dot; user menu open/closed; search open/closed.
- **Sidebar:** Active item; hover; collapse toggle hover.
- **Notification center:** Loading (skeleton), empty, error (retry), unread/read items; new arrival (slide-in, badge update).

**6. Role-based variations**

| Role | Audit link | ECS/CMC | Enforcement | VCI Governance | System Config |
|------|------------|---------|-------------|----------------|---------------|
| **All** | — | If active or historical | — | — | — |
| **MOH Tier 1 & 2** | Sidebar "Audit" → `/audit/logs` | If active/historical | Section visible | "Governance" visible | Tier 1 only |
| **Company** | Hidden | If active/historical | Hidden (own actions elsewhere) | Hidden | — |

- **Enforcement:** MOH Tier 1 & 2 only. Companies do not see Enforcement nav; they access own actions via other flows.
- **System Config:** Tier 1 only (0.5.1.14).
- **ECS/CMC:** Shown only if module active or historical data exists.

**7. Edge cases & validation**

- Notification list capped at 10–15; messages truncate; "99+" for badge.
- Sidebar state persisted (e.g. localStorage). Active route from path.
- Fallbacks: avatar → initials; notification load error → retry; offline: cached nav where applicable.
- Accessibility: skip link "Skip to main content"; focus trap in dropdowns/drawer; ARIA labels; 40×40 min touch targets.

| Function | rpc-functions.md | Migration | Match |

**2. Signatures & return types**

| Function | Documented signature | Implementation | Returns |
|----------|----------------------|----------------|---------|
| `shared_get_user_permissions` | `(user_id uuid)` | `(user_id uuid)` | `jsonb`: `{ role, company_id, permissions }` or `{ error, user_id }` |
| `shared_get_notifications` | `(p_limit int DEFAULT 50, p_offset int DEFAULT 0)` | `(p_limit int DEFAULT 50, p_offset int DEFAULT 0)` | `jsonb`: `{ data: [...] }` |

- **shared_get_user_permissions:** Reads `users` for given `user_id`; returns role, company_id, permissions array. Caller passes `auth.uid()` for self. RLS restricts which users are visible. Layout uses it for header (avatar, role), sidebar (role-based nav), and permissions checks.
- **shared_get_notifications:** Reads `notifications` for `user_id = auth.uid()`, ordered by `created_at DESC`. Limit 1–500, default 50; offset ≥ 0. Layout uses it for notification center list and unread badge.

**3. Error handling**

| Function | Success | Error / edge |
|----------|---------|---------------|
| `shared_get_user_permissions` | `{ role, company_id, permissions }` | User missing/inactive → `{ error: 'user_not_found', user_id }` |
| `shared_get_notifications` | `{ data: [...] }` | No rows → `{ data: [] }`; no explicit error payload |

Layout must handle: (1) `user_not_found` when resolving permissions; (2) empty `data` for notifications (empty state).

**4. Permissions & access**

| Function | Security | RLS | GRANT |
|----------|----------|-----|-------|
| `shared_get_user_permissions` | SECURITY INVOKER | Uses `users` RLS (own / MOH / same-company) | `authenticated`, `service_role` |
| `shared_get_notifications` | SECURITY INVOKER | Uses `notifications` RLS (own only) | `authenticated`, `service_role` |

Both run as caller; RLS enforces access. Frontend must call with authenticated Supabase client (JWT).

**5. Feature-index alignment**

- **Header (0.5.1.15):** `users`, `notifications` → `shared_get_user_permissions`, notification data via `shared_get_notifications`. ✅  
- **Sidebar (0.5.1.16):** `users.role` → `shared_get_user_permissions`. ✅  
- **Notification center (0.5.1.17):** `notifications` → `shared_get_notifications`. ✅  

**6. Related layout APIs (notification center)**

- **`shared_mark_notification_read(p_notification_id uuid)`:** Implemented in same migration. Returns `{ success }` or `{ success: false, error: 'not_found_or_forbidden' }`. Used for “Mark as read” and “Mark all read” (iterate IDs). GRANT to `authenticated`, `service_role`. ✅  
- **`system_get_status()`:** Optional for module visibility (ECS/CMC conditional). Implemented in `20260127151100`; RLS restricts to Tier 1 / system_admin. Use if layout reads module status from backend.

**7. Call conventions**

- **shared_get_user_permissions:** `supabase.rpc('shared_get_user_permissions', { user_id: session.user.id })` (or `auth.uid()` equivalent).  
- **shared_get_notifications:** `supabase.rpc('shared_get_notifications', { p_limit: 15, p_offset: 0 })` for notification center (wireframe: max 10–15 in dropdown).
